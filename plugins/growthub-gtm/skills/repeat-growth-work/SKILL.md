# Repeat the work that has already proved useful

Start from an actual accepted result, saved Character and destination. Establish
what should repeat and the exact schedule/timezone the user wants. Preserve the
existing method/version, provider account/model, connector grants, brand version
and output destination. A plugin install or request for a draft grants no schedule.

Use the existing Growthub Routines surface in the same authenticated account:
https://www.growthub.ai/dashboard/workflow/chat?view=routines
Use the selected Character's native Routine controls when already open. Keep the
existing authentication and publication process; do not create new credentials,
wrap a private browser session or call guessed mutation endpoints.

The presently verified CEO MCP has no Routine lifecycle tools. Do not invent
`create_routine`, `publish_routine` or `run_routine` calls. On a surface with the
user's authorized browser/computer access, complete the existing UI journey,
confirm the exact saved publication and observe its actual run. On a surface
without that access, provide the existing continuation link and the reviewed
schedule/inputs. State that publication/run is pending; do not promise a fully
automatic external-provider schedule.

Read the existing publication, run identity, terminal outcome, saved reply and
independent destination effect. Pending output, a schedule row or green toast
is not a successful recurring result. Verify duplicate absence before retrying.
Never add cron, a provider timer, a second queue or another customer Routine for
the same cadence. Leave existing approved recurring work unchanged.

After a successful run, explain the next useful action. Upgrades follow current
Growthub entitlements and the customer's actual need; do not invent plan access,
credit balances, ROI or time savings.
